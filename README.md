# dsh-silent-model-switch

一个 Host 侧 DeepSeek Harness（DSH）Cordis 插件。它在 `agent/pre-step` waterfall 阶段移除模型切换通知，避免这类内部通知进入模型请求。

## 行为

插件只检查结构化来源字段：

```ts
message.source?.kind === 'model-selection'
```

它不会进行文本匹配，也不会改写、重排或新增其他消息。若下游返回 `enter`，插件过滤其中的 `messages`；若没有匹配项，则原样返回同一个 decision 对象。插件自身不会创建 `reject` 决策，并保留下游已有的非 `enter` 决策。

### 实际通知与监听器顺序

当前 DSH 的 `installModelSelection()` 生成的通知包含以下字段（省略消息 id）：

```ts
{
  role: 'user',
  content: [{
    type: 'text',
    text: '[model changed: assistant turns above this point were generated by gpt-5.6-sol; the session continues with gpt-6.1-sol]'
  }],
  source: {
    kind: 'model-selection',
    form: 'notice',
    summary: 'gpt-5.6-sol → gpt-6.1-sol'
  }
}
```

这条消息不是必须预先出现在 `payload.messages` 中：DSH 的模型切换监听器以 `{ prepend: true }` 注册，在 `await next()` 返回后追加通知。因此过滤器必须包裹该监听器，在返回路径上最后过滤。

1.0.1 修复了 1.0.0 的顺序遗漏：过滤监听器同样前置注册；每次 `agent/created`（新建或恢复 Agent 的 setup 已完成、输入尚未放行）时，移除旧注册并重新前置，始终只保留一个插件拥有的过滤监听器。这样既覆盖安装前已存在的 Agent，也覆盖安装后新建或恢复的 Agent，且 `inject` 仍为空。

**范围限制：**只阻止新通知进入本步已接纳的消息，不回溯删除已写入历史的旧通知。用户自己输入完全相同的文本，只要 `source.kind` 不是 `model-selection`，就不会被删除。

## 开发

要求 Node.js 20 或更高版本，并使用 pnpm：

```sh
pnpm install
pnpm run typecheck
pnpm test
pnpm run pack:check
```

构建产物输出到 `lib/`。

## 安装到 DSH

本包通过 `dsh.bundle.patch` 声明了 Cordis bundle。完成构建后，可将包目录作为本地 bundle 安装到 DeepSeek Harness；补丁会挂载同名插件 `dsh-silent-model-switch`，无需配置项或强制注入依赖。

## 兼容性

当前代码针对以下公开 API 编译和验证：

- `@deepseek-ai/cordis` 4.1.x
- `@deepseek-ai/dsh-agent` 0.2.0-0

## 手动升级检查

[迁移工作流](<.github/workflows/dsh-migrate.yml>) 固定使用 [QZLin/dsh-migrate-bot v3.0.1](https://github.com/QZLin/dsh-migrate-bot/releases/tag/v3.0.1) 对应的提交，仅保留 `workflow_dispatch`；没有定时、push、PR 或其他事件触发。

该版本不调用 LLM，也不自动修复插件源码：只更新 DSH 依赖范围和插件 patch 版本，并运行现有的 build、typecheck、test 及启动检查。检查失败时提交草稿 PR，由维护者手动处理。不需要 DeepSeek API key。v3 起 Action 为 composite 型，每次运行在 runner 上安装 Node 与 pnpm 后自源码构建，不再拉取容器镜像。

bot 本身只改 `package.json`。工作流在它之后追加两个确定性步骤，把提案补全为可直接合并的状态：`pnpm install --lockfile-only` 刷新 `pnpm-lock.yaml`，[scripts/sync-metadata.mjs](<scripts/sync-metadata.mjs>) 把 README 兼容性列表中的 `@deepseek-ai/*` 版本改成 manifest 声明的版本（`4.1.x` 这类只写到次版本的引用在次版本未变时保持原样）。两者都没有变化时不会产生多余提交。

检查全部通过的提案会被自动 squash 合并进默认分支，无需人工确认；这一步对合并结果没有复核环节，只有在你需要先看 diff 时才应关闭。若某个检查失败，bot 打开的是 **草稿** PR，自动合并会跳过它，留给你手动处理。手动运行时可用 `auto_merge=false` 只生成提案而不合并。

在仓库 Settings → Actions → General → Workflow permissions 中启用 **Allow GitHub Actions to create and approve pull requests**。工作流使用仓库自带的 `GITHUB_TOKEN`（`contents`、`issues`、`pull-requests` 写权限）推送提案分支、创建 issue 和 PR，因此不需要额外创建 PAT 或 Secret。缺少该开关时推送和建 issue 都会成功，只有建 PR 会返回 HTTP 403。

配置合并到默认分支后，在 Actions → dsh-migrate → Run workflow 手动运行，或使用 GitHub CLI：

```sh
# 目标为空时使用最新的 dsh release。
gh workflow run dsh-migrate.yml

# 指定目标 release；必要时重新处理已运行的版本。
gh workflow run dsh-migrate.yml -f dsh_release=dsh-v0.2.2-rc.1 -f bump_again=true
```

工作流固定 Action 提交以避免静默更新；升级 bot 时需显式更新固定提交。迁移结果和检查输出见运行摘要及提案 PR，`dsh-migrate/state` 分支用于保存记录，不要合并到默认分支。
