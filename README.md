# dsh-silent-model-switch

一个 Host 侧 DeepSeek Harness（DSH）Cordis 插件。它在 `agent/pre-step` waterfall 阶段移除模型切换通知，避免这类内部通知进入模型请求。

## 行为

插件只检查结构化来源字段：

```ts
message.source?.kind === 'model-selection'
```

它不会进行文本匹配，也不会改写、重排或新增其他消息。若下游返回 `enter`，插件过滤其中的 `messages`；若没有匹配项，则原样返回同一个 decision 对象。插件自身不会创建 `reject` 决策，并保留下游已有的非 `enter` 决策。

### 实际通知与监听器顺序

当前 DSH 的 `installModelSelection()` 生成的通知包含以下字段（省略消息 id）：

```ts
{
  role: 'user',
  content: [{
    type: 'text',
    text: '[model changed: assistant turns above this point were generated by gpt-5.6-sol; the session continues with gpt-6.1-sol]'
  }],
  source: {
    kind: 'model-selection',
    form: 'notice',
    summary: 'gpt-5.6-sol → gpt-6.1-sol'
  }
}
```

这条消息不是必须预先出现在 `payload.messages` 中：DSH 的模型切换监听器以 `{ prepend: true }` 注册，在 `await next()` 返回后追加通知。因此过滤器必须包裹该监听器，在返回路径上最后过滤。

1.0.1 修复了 1.0.0 的顺序遗漏：过滤监听器同样前置注册；每次 `agent/created`（新建或恢复 Agent 的 setup 已完成、输入尚未放行）时，移除旧注册并重新前置，始终只保留一个插件拥有的过滤监听器。这样既覆盖安装前已存在的 Agent，也覆盖安装后新建或恢复的 Agent，且 `inject` 仍为空。

**范围限制：**只阻止新通知进入本步已接纳的消息，不回溯删除已写入历史的旧通知。用户自己输入完全相同的文本，只要 `source.kind` 不是 `model-selection`，就不会被删除。

## 开发

要求 Node.js 20 或更高版本，并使用 pnpm：

```sh
pnpm install
pnpm run typecheck
pnpm test
pnpm run pack:check
```

构建产物输出到 `lib/`。

## 安装到 DSH

本包通过 `dsh.bundle.patch` 声明了 Cordis bundle。完成构建后，可将包目录作为本地 bundle 安装到 DeepSeek Harness；补丁会挂载同名插件 `dsh-silent-model-switch`，无需配置项或强制注入依赖。

## 兼容性

当前代码针对以下公开 API 编译和验证：

- `@deepseek-ai/cordis` 4.1.x
- `@deepseek-ai/dsh-agent` 0.2.2-rc.1
